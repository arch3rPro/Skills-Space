## Source support

GUI preview supports absolute local directories (the UI expands `~`), owner/repo with optional subdirectory/ref, GitHub/GitLab tree links, Git HTTP(S), SSH, git/file URLs. It uses existing Git authentication; credential-bearing HTTP URLs are rejected. Private/SSH authentication has not been verified against a real host. Discovery is bounded (ordinary recursive depth 5 plus original plugin priority-directory immediate children, 200 skills), skips symlink/ignored directories, defaults to hiding internal skills (explicit opt-in available in the source step) and rejects duplicate names, including hidden-name collisions. Well-known HTTP(S) sources now use bounded original-provider preview for v1 multi-file and v2 Markdown/ZIP/TAR.GZ artifacts; arbitrary standalone file URLs without a working discovery index remain unavailable. Unsupported/failed preview never means an empty repository or permission to install all skills. Installation rechecks selected preview fingerprints before executing the original CLI; later concurrent source changes can still yield an uncertain post-verification result.

## State and side effects

- Global installs use upstream canonical storage, Agent directories and global .skill-lock.json where applicable. Project installs use the selected cwd, Agent directories and skills-lock.json.
- Universal Agents use the canonical .agents/skills directory even when their globalSkillsDir definition differs. Symlink/copy semantics, shared directories and lock updates are upstream-owned. The desktop does not create a parallel deployment ledger. Selected removal can clean canonical storage and lock metadata, depending on upstream Agent detection; other observed Agents can be affected.
- Upstream add/update/remove are mutating commands. In this baseline check aliases update; it must never power a read-only button.
- User-triggered read-only checks clone recorded GitHub/GitLab/Git sources for global and project scopes. Global locks use skillFolderHash; project locks use computedHash. GitHub global locks can contain a Git tree SHA or fallback folder SHA-256; both representations are verified. Current requires matching source hash and actual installed content. Local edits, unknown provenance, unsupported or uninspectable sources remain unknown.
- The original CLI is eligible to execute remotely later through SSH with explicit cwd/user/runtime. This release rejects non-local targets and makes no claim that SSH workflows work.

## Upgrade checklist

Before changing the pin, compare aliases and parameter parsers, list JSON shape, Agent path metadata, Node engine requirement, source discovery and lock formats. Re-run isolated real-CLI project/global symlink/copy install, selected removal, failure verification and packaging checks. Extend this map when integrating another command; do not infer compatibility from semver alone.

## Removal semantics verified on 2026-10-13

`getAgentBaseDir` maps universal Agents (including Codex and OpenCode) to `.agents/skills` even when a legacy globalSkillsDir is declared. `removeCommand` skips canonical content during per-Agent cleanup, deletes selected dedicated links/copies, then checks **all remaining detected Agent paths**, without distinguishing copies from links. A remaining independent copy can therefore keep canonical content. Source lock entries are removed even if content/copies remain. No separate "unlink only" upstream command exists.

The desktop previews concrete paths and expands a shared-content selection to that content's universal/linked Agents **per skill**. It never silently includes independent copies; the confirmation can explicitly include them and regenerate the plan. Plan equality is rechecked before execution. Results distinguish actual path removal, retained selected targets, retained copies, broken links, inspection errors and lock cleanup. Known retained selected targets are incomplete removal, rather than unexplained uncertainty. Unexpected shared cleanup remains visible as an additional effect. The original CLI bytes and mutation ownership remain unchanged.

## Init integration (2026-10-13)

Pinned runInit takes the first positional name, otherwise cwd basename; with a name it recursively creates that subdirectory, otherwise writes cwd/SKILL.md. Existing SKILL.md returns without writing (including exit zero), so the adapter checks actual files rather than prose. GUI accepts portable 1–64 lowercase ASCII letters/digits/hyphens/underscores starting with an alphanumeric character: upstream directly interpolates the name into both path and YAML. Differently named current directories can use a named child directory. Location preview is read-only, canonicalizes the parent, rejects file/symlink destinations and any existing SKILL.md entry (including dangling links), and execution revalidates the confirmed plan under the app mutation lock. The original init performs all writes; valid readable metadata plus successful execution is required for a created result. Missing files fail; unreadable/invalid or unsuccessful-but-present output remains review-required. No automatic retry or cleanup. This is not an atomic transaction against external concurrent filesystem writes; upstream has its own exists/write window.

Created source content is shown in the existing modal style, can be opened through the OS, and then passed to the ordinary preview/install wizard with skill preselection. Source location and installation scope remain distinct. Creation itself does not call add, list an installation, or write lock entries. Installation and removal leave the source template intact.

## Project lock restoration integration (2026-10-13)

`runInstallFromLock` reads the full project lock, groups non-node_modules entries by buildLocalUpdateSource and invokes original runAdd with explicit locked names, all getUniversalAgents targets and yes=true. It fetches current sources/ref, not the recorded computedHash as an immutable content pin. Dedicated Agent links/copies are not rebuilt; existing links to canonical content may change. Subagent targets are not replayed. No per-skill/per-Agent selection is exposed by this command.

If any node_modules entries exist, the command delegates to runSync for the entire dependency scan. This may install skills absent from the lock. A matching source computedHash skips installation even if the destination is missing. --force only controls this dependency phase and reinstalls all discovered dependency skills; it does not force a Git revision. The GUI previews package roots and immediate package/skills/.agents/skills children using the same pinned discovery shape, including scoped/pnpm-linked packages, with bounded read-only inspection. Duplicate names/colliding destinations and remote/dependency collisions block execution, because upstream discovery order can otherwise overwrite a skill.

The restore adapter requires a regular version-1 lock with 1–200 entries, at most 1 MiB; unknown or malformed locks are errors, never empty success. SHA-256 lock fingerprinting uses the existing bundled Node read-only helper. Canonical project scope, source hashes, target types/link targets/content hashes and existing installations are rechecked before original CLI execution. Linked shared-root ancestors are blocked. Local and Git/GitHub/GitLab sources use existing preview/source snapshots; missing generic Git sourceUrl, internal/plugin/subagent entries and unsupported/uninspectable sources block full command execution rather than silently skipping unknown writes. Inherited INSTALL_INTERNAL_SKILLS is cleared for this command to match the preview. getUniversalAgents visibility is derived from the unchanged CLI table during staging.

Results inspect content against the source installation expectation, source type/current computedHash, lock changes and actual path state. Missing targets fail; verified unchanged targets are already satisfied; restored files and verified locks are reported individually, including partial outcomes after exit zero. Unexpected non-target installation/link/lock changes remain visible and prevent complete verification. Retry returns to inspection of the whole command plan and requires new confirmation; there is no automatic rollback, selective lock rewrite or separate restore engine. Source changes may refresh lock records; this workflow is not an exact-version rollback.

## Source parser integration (2026-10-13)

The published CLI has no parser export. The read-only inspect-upstream-source helper reads its unchanged bundled dist file and evaluates only the original DEFAULT_GITHUB_HOST-to-isWellKnownUrl function block in a restricted VM. User input is a bound value, never interpolated executable text. The block has no CLI dispatch, filesystem writes or supplied network capability. Boundary checks fail closed; staging smoke-tests a ref/filter result against the pinned package. No copied alias table, independently maintained parser implementation or alternate write command is introduced. Original bin/dist bytes remain unchanged.

Preview and source snapshots use that parser's resolved repository URL/ref/subpath. Absolute local paths resolve according to upstream's path semantics; relative paths remain unavailable because preview has no selected-project cwd contract. Read-only document inspection still applies existing bounds and refuses unknown provider types, credentials/query URLs, unsafe subpaths or unsupported literal fragments. GH_HOST is inherited consistently for production parsing and original execution; isolated test environments clear it unless a parser fixture explicitly supplies it.

A resolved skillFilter restricts preview to one visible exact metadata name (case-insensitive). The GUI explains the source-specified skill and preselects that resolved name; installation still requires target choice and explicit confirmation. Backend re-preview rejects extra names, missing/hidden matches and collisions, including public/internal names differing only by case. The original source string is passed unchanged to add, so its appended source filter cannot silently install an unreviewed extra skill. Internal skill visibility remains an explicit separate option. Plugin display-name filters without a uniquely inspectable metadata identity remain unavailable.

Pinned quirks are preserved, not corrected: aliases match the original exact alias input; some prefix/URL combinations discard fragment skill filters in upstream's recursive parser. The adapter uses the returned contract rather than promising every apparent @/fragment spelling has filtering semantics. A source with no returned filter follows ordinary explicit GUI selection. ref decoding, alias resolution and GH_HOST validation are owned by the original parser; unsupported sources never become empty successful previews.


## Eve project integration (2026-10-13)

Eve has no globalSkillsDir. Project add can select root and existing agent/subagents/name directories with --subagent root/name; original symlink mode uses the Eve destination itself as canonical storage. It therefore creates independent Eve directories while ordinary Agents retain their normal shared/link behavior. Copy mode also writes transformed Eve directories. The original stripIgnoredEveFrontmatter removes name and unsupported fields, retains description/license and string metadata, and applies to every SKILL.md regardless of case, including nested files. The read-only inspect-eve helper evaluates that unchanged formatter and parseFrontmatter from bundled dist with the existing YAML dependency. It builds expected contents without writing staging copies or replacing the CLI.

Inventory observes the root and each subagent path, recovers folder identity against an unambiguous matching lock key, and labels the actual locations. A lock source applies to Eve only when its recorded subagents (or implicit root) include that actual path. Reinstalling into a different subset replaces the single per-name project lock selection; unselected old copies stay visible with unknown source when no longer covered. Read-only checks compare Eve converted contents and normal Agent raw contents against the same source snapshot. Actual Git update uses original update and requires every recorded Eve destination, converted content and source lock hash to match; malformed/changed subagent records and linked parent directories fail closed.

Original remove has no --subagent option: selecting Eve traverses root and all existing subagent destinations for that name. Confirmation includes same-name directories lacking valid metadata and existing links, in addition to ordinary inventory records. Multiple Eve copies are therefore allowed only as a reviewed whole-Agent remove; other Agent same-name ambiguity remains blocked. Existing shared content/other Agent relationships follow the same ordinary removal expansion/report. No selective deletion executor or lock repair is added.

Current bounds: project only; up to 100 existing portable subagent names; Eve skill names use unique nonempty ASCII destinations within 200 characters; formatter input within 64 KiB JSON and ordinary tree/document bounds. Reserved/unportable names, symlink installation parents, absent destinations and uninspectable conversions are rejected rather than silently normalized. Flat Eve .md provider files are surfaced as inventory warnings for direct inspection, not claimed as supported folder skills. Eve in experimental_sync and subagent locks in experimental_install remain separate pending workflows. Windows/Linux, real Eve execution/loading and authenticated private/SSH sources are not validated by local file fixtures.

Folder content SHA-256 is now available even when standard name metadata is absent or invalid. Metadata validation still controls skill discovery; content-only observation lets dependency installation and lock restoration verify that unrelated converted Eve files remained unchanged. The helper remains read-only and shares the existing bounded hashing implementation.


## Plugin discovery integration (2026-10-13)

The pinned getPluginSkillPaths/getPluginGroupings functions are evaluated read-only from the unchanged dist file. Only pre-read manifests are supplied; no main, network or write APIs are exposed. ## Well-known/download integration (2026-10-13)

Pinned parseSource classifies ordinary HTTP(S) URLs as well-known (except the upstream Git/host exclusions). It does not implement a generic standalone Markdown/archive URL installer. Original handleWellKnownSkills calls fetchAllSkills, discovering .well-known/agent-skills/index.json then .well-known/skills/index.json at the supplied base path and host root in original candidate order. It does not narrow selection merely because the input path looks like one skill. GUI shows the complete reliably fetched candidate list and passes explicit installation names to original add, never implicit --yes-all. A standalone file URL without a working index fails clearly.

The read-only helper evaluates the unchanged WellKnownProvider, parseFrontmatter and sanitizeMetadata with only bounded network, crypto and decompression primitives. v1 fetches SKILL.md plus declared attachments (binary bytes retained); v2 verifies sha256 digests on standalone skill-md or ZIP/TAR.GZ artifacts before original parsing/extraction. The helper keeps the first candidate with any valid skills according to original order, but rejects partially readable candidates instead of presenting a subset while the CLI might discover more. Missing attachments, bad digests, malformed documents, duplicate names, unsafe or case-conflicting paths, file/directory conflicts and index/document installation-name differences block preview. Internal skills remain hidden by default; collisions are checked before hiding. No source files or installation directories are written by this helper.

Preview bounds: 200 skills, 200 files per skill, 1 MiB per index, 512 KiB per artifact/attachment and combined decoded skill content, 4 MiB total response bytes, 2000 file-path/metadata constraints from the ordinary adapter, 10-second HTTP request timeout and 5 redirects, existing 120-second process timeout. Decompression output is capped at 1 MiB per call in addition to original archive validation. Credentials/query/fragments and non-HTTP(S) download/redirect URLs are rejected; advertised cross-host HTTP(S) artifacts are permitted. .git/node_modules payload paths are rejected because ordinary inventory hashing intentionally skips those directories. Output is capped below the native capture limit. These are conservative GUI verification bounds, not upstream limitations or a replacement downloader for writes.

Source fingerprints bind original-compatible folder content hash, artifact URL and index entry. Confirmation re-fetches before original add; a later race remains observable through installed byte comparison. Provider installation preserves files such as metadata.json and Python caches, so expected signatures use the full downloaded map rather than ordinary Git-copy exclusions. Every selected Agent's actual content plus provider lock record is verified. Global locks store sourceType=well-known, artifact/SKILL.md sourceUrl and an empty skillFolderHash; project locks store hostname source and computedHash, without a discovery URL or skillPath. Unique target skillsDir forces original copy mode even if --copy was not passed; multiple directories allow original links. Eve's provider handler ignores --subagent and records different hashes, so Eve targets are excluded rather than claiming the ordinary Eve workflow applies.

These lock records do not provide the current automatic Git update/check contract. GUI shows unknown with a specific re-preview instruction, does not invent version state and uses original add for refresh. Only global URLs under /.well-known/ allow reconstructing the original host/base via the existing upstream-style prefix rule; arbitrary artifact URLs and project hostname records require source re-entry. Detail re-preview avoids treating an artifact URL/hostname as a reliably reconstructable source. Update/source-lock restore for providers and mismatched installation/document identities are not claimed as delivered.


## Temporary use integration (2026-10-13)

The pinned USE_AGENT_CONFIGS is staged read-only from the original literal table (currently claude-code -> claude and codex -> codex, empty additional args). Executable lookup is independent of Agent configuration detection. GUI confirms a single source skill, prompt mode or one available Agent, and the real working directory (HOME or an explicitly selected project). It passes original use, explicit --skill and --full-depth; no --yes, wildcard/multiple Agent, yolo or invented permission option is added. Original source selectors remain consistent with the selected skill. OpenClaw owner detection follows original getOwnerRepo and requires explicit risk acceptance before the original flag is passed.

Original runUse removes cloneTempDir but intentionally retains skills-use materialization after prompt/Agent exit. Desktop session TMPDIR is a private cache subdirectory. Ordinary use excludes metadata.json and .git/Python cache directories but retains worktree .git files and includes node_modules, unlike ordinary add expectations; provider map materialization retains its entire file map. A separate bounded source-use signature captures these exact differences. Confirmation rechecks the selected source and complete use signature. The per-session Agent bridge compares every materialized byte and the unchanged buildUsePrompt result before invoking the actual Agent executable with exactly the original prompt argument; prompt-only output receives the same verification. Exit zero without files/prompt or without actual Agent invocation is a failed session, not verified use.

macOS uses the system Terminal and a generated static-path .command launcher, with source/prompt data passed through JSON/argv rather than interpolated shell text. The local bridge affects only a session's child PATH; installed commands remain untouched. Real Agent I/O inherits the terminal. Structured runner/bridge metadata records preparing, running, exit code, failure, cancellation and supporting-file location. Terminal prose is diagnostic, and process success is not task-completion evidence. Preparation times out at 120 seconds; an interactive Agent that has started has no fixed time limit. Normal CLI exit leaves surviving process-group jobs running and keeps the controller/files; Stop terminates that owned group with a grace period. Crashed/unknown process ownership is review-required, without guessing PIDs to kill. Deliberately detached daemons are outside process-group containment.

Closing the modal retains sessions. Reopening observes private cache records; explicit release validates the session identifier/root, checks tracked processes and claims filesystem ownership before deleting only that session. A cancelled or released delayed terminal launch cannot later start the Agent. Copied prompts retain absolute support paths while GUI paths abbreviate HOME; release invalidates these references. Cache roots are limited to 50 retained sessions, with ordinary 4 MiB/2000-entry temporary-content bounds and 512 KiB prompt output. No installed inventory or source lock is fabricated, no user skill directory is cleaned, and no credentials are stored in configuration. Windows process control and Linux external-terminal launch remain unavailable; real authenticated Codex/Claude tasks and other operating systems are not certified by the fixtures.
