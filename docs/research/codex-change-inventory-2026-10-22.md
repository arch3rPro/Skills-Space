# Codex 增强累计改动清单

日期：2026-10-22。用途：回答“累计改了什么”，供用户决定收敛范围和逐项优化。本清单不是功能完成声明，也不授权后续删除、重构或进入 B2。

核对依据：当前工作树、相对 HEAD 的差异、Codex 专属新增文件及[逐项对账记录](codex-implementation-reconciliation-2026-10-22.md)。这里描述现存改动；多轮已撤回内容另列。工作树包含其他任务，不能把全部未提交文件、行数或设计基线差异归到 Codex。

## 1. 总体改动面

累计新增 18 个 Codex 专属源码/测试文件，以及此前的 4 份 Codex 研究、方案和对账文档；本清单是另新增的第 5 份文档。此外修改了原有主页面、通用库存、生命周期入口、Agent 分类、偏好、测试入口和架构说明。

这次并非只加一个 Codex 设置页：已经形成“运行端接入 → 库存合并 → 技能规则 → 插件管理 → 更新恢复 → 共享页面适配”的整条实现链。18 个文件不等于 18 项功能，也不包含共享文件中的 Codex 修改。

## 6. 收敛和逐项优化如何使用这份清单

建议先按改动依赖核对，而不是继续按某个按钮补丁式修复：

1. **先确定保留哪些改动组**：本地接入与库存（C09–C13）、技能和规则（C03–C06/C14）、本地插件（C07/C08/C15）、远程插件（C13/C15 的远程分支）、更新恢复（C16–C18）。这是待用户取舍的分组，不代表取消已批准功能。
2. **先撤无必要界面，再修基础数据**：正常提示、未载入技术筛选、运行信息不是核心能力；但仅撤它们不能算修好状态读取、独立启停或远端检查。
3. **每次优化闭合一条链**：例如技能启停必须同时检查读取、规则保存、卡片、批量、刷新/重启及插件停用时的行为；不是只改开关颜色或提示。
4. **性能随涉及功能验收**：库存、详情、插件页分别测量，不以一个小样本计时代替全局/项目真实页面表现。
5. **收敛必须包含清理成本**：停用某组能力时同时核对页面入口、命令、库存字段、通用生命周期限制、偏好及恢复记录；不能只藏入口，也不能删掉其他任务的共享改动。

本轮只记录累计改动，不修改实现、不撤功能、不改设计基线、不运行构建、不提交。已通过的 B1 测试来自上一批记录，本次没有重跑或扩大其结论。


逐项保留、简化、撤回建议及校验减负见[Codex 增强收敛方案](codex-scope-reduction-plan-2026-10-22.md)。该方案待核对，未执行。
