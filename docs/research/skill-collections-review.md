# 技能分类、Pi 配置入口与候选配置

日期：2026-10-15。状态：本轮页面拆分与配置入口已实现并验证；后文候选配置仅为调研建议，未新增写入能力。设计遵循 [UI 基线](../design/ui-system.md)，Pi 配置边界见 [0006](../specs/0006-pi-skill-management.md)。

## 已确认并实施

- 设置 → AGENT管理：Pi 卡片保留进入配置页的按钮，并增加设置图标；无配置页的其他 Agent 身份与数量区域为静态内容，点击不跳转。原有拖动排序、显示开关、状态和数量保留。
- 技能空间与 Agent 库存使用一致的“托管技能 / Agent 技能”页签，复用现有行式 Tabs、工具栏、等高卡片和品牌图标。切换清空批量选择；搜索、Agent 筛选及项目范围仍约束当前清单。卡片 Agent 图标进入对应 Agent 时保留分类，侧栏切换 Agent 默认回到托管页；详情返回保留原分类。
- 托管页保留添加、检查更新、批量管理和原版 CLI 支持的卡片操作；Agent 技能页提供查看、打开目录、技能测试，以及 Pi 页面实际可用的原生启停。隐藏该页不适用的更新、卸载、批量和项目安装入口，不创建虚假的 Hermes 原生启停或更新能力。详情仍可显式预览安装到其他 Agent。
- 来源统一标注“内置 / 扩展包 / 本地目录”，不将 Pi 原生技能显示为未知来源，也不把所有未托管技能标为内置。卡片不增加新说明段落；扩展包的实际声明来源在详情显示。

## 分类依据

分类是管理能力的界面分区，不是对历史安装者的证明，底层库存和 CLI 记录保持原样。

1. 有有效上游来源关联的 `cliManaged` 条目优先进入托管页，同一物理库存记录不重复展示。
2. Hermes 已由内置清单确认的技能、配置的额外目录、无法由 CLI 标准目标寻址的分类目录条目，进入 Agent 技能页。
3. Pi 扩展包、配置的附加位置、原生目录条目进入 Agent 技能页；Pi 自动发现且位于标准共享安装目标的条目保留在托管页。
4. 普通标准安装目标中没有来源记录的技能继续保留既有管理行为，包括上游可能不写来源锁的直接下载。Hermes 标准根目录的无来源条目也不擅自冒称内置；来源确实无法确定时保留“未知来源”。
5. 托管页的同名冲突和删除／更新限制仍依据完整库存校验，不能因为分了页就忽略另一个页面的同名安装并放开危险操作。安装／更新／卸载实现未修改。

## Pi 还可加入哪些技能配置（仅建议）

依据仍为已核对的 Pi 1.1.0 固定源码 `abe508e1b89912adde45528136c3221eb69acdd7`，不等同于任意旧版 Pi 均支持同一合同。

| 候选 | 原生位置／参数 | 建议与边界 |
| --- | --- | --- |
| 技能命令补全 | `settings.json` → `enableSkillCommands`，默认 true | 最小的下一项开关。控制交互命令发现，不等于技能启停；手动输入 `/skill:name` 仍能工作。 |
| 附加单个技能文件 | `settings.json` → `skills[]` | 当前界面优先选择目录；原生也接受技能 Markdown 文件。可扩展现有位置选择器，不新增单独管理模块。 |
| 包内技能选择 | `packages[].skills` | 当前普通包内技能已经支持卡片启停；后续可做按包集中选择。空数组禁用这一类资源，不等于卸载包；项目 `autoload:false` 增量仍需单独设计，不能混用普通包过滤语义。 |
| 自动可用／仅手动 | `SKILL.md` → `disable-model-invocation` | false／未设置时可供 AI 选择，也可手动调用；true 时仅显式调用。适合放在卡片更多操作，不再堆常驻开关。但它修改技能文件，共享文件会影响其他读取该字段的 Agent，不能伪装为仅属于 Pi 的设置。当前仅只读识别 `manualOnly`，未接入写入。 |

现有启停通过 Pi 资源过滤决定是否进入技能清单；调用方式决定已可用技能是否参与 AI 自动选择，两者不是同一开关。不承诺 AI 在“自动可用”时必然调用该技能，也不把启用状态解释成已加载到正在运行的会话。

## Agent 管理卡片对齐复查

此前配置入口与技能库存的验证没有充分检查 Agent 管理卡片的内部对齐，不能据此认定该页面视觉验收完成。实际发现头部顶对齐导致开关与设置图标错位，Pi 的按钮容器与其他 Agent 的静态容器不同，长名称和数量也缺少统一的溢出规则。

- 统一身份区域、名称与数量的行高，拖动手柄、品牌图标、设置按钮和显示开关沿同一中线排列。设置按钮移至右侧独立操作位，其他卡片保留同等宽度；底部状态和路径共用基线。内容截断而不撑高卡片，不增加固定外框高度或新配色。
- 实际桌面检查：深色 Vercel／中文 16px 的 1280×828 与 960×660 窗口；浅色 Claude／英文 18px 的相同两种窗口。检查 Pi、有无配置入口、零和多位数量、三种安装状态，以及滚动后的长名称和长路径；卡片区域与控件对齐，窄窗口长内容省略显示。英文大字号窄窗口的工具栏按既有规则换行，重新检测保持右对齐。
- 点击独立 Pi 设置图标可进入管理页并返回。未改排序、显示、检测或技能生命周期逻辑；未执行安装／卸载测试。严格 TS、前端构建、debug 应用打包通过；保留既有 chunk 提示。应用已重新打开供复查，未提交。
