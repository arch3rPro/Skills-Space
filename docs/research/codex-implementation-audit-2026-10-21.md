## 修正方向

1. 先重划界面职责：Codex 技能页保留统一技能库存；插件作为原生资源的管理对象，入口放在该 Agent 原生资源工具栏，通过现有管理流程操作。插件生命周期移出“设置”。不新增顶层侧栏页面。Codex 设置只承载有实际编辑效果且已验证的配置；没有可编辑配置时不保留空壳入口。
2. 详情恢复统一结构：移除正文前额外的管理 Field；来源、路径进入已有元数据，操作进入标题区／更多菜单。若保留插件管理入口，必须定位当前插件并保留返回上下文。
3. 拆分 canToggleSkill、canTogglePlugin、canInstall、canUninstall 及不可用原因；用户级启停能力不由市场下载／安装来源决定。先用 Git 市场、已安装本地来源及禁用状态隔离样本验证原生配置契约，再开放对应动作；不直接取消安全边界或改写真实用户插件。
4. 技能与插件操作必须显示真实对象：插件整包开关明确影响同包所有资源，普通技能启停只操作所选技能。避免同一批量栏显示两套容易混淆的启停动作；整包卸载集中到插件管理，不能在每张技能卡片重复。
5. 统一库存与快照读取；区分读取失败、策略限制、版本不兼容和未安装；失败保留可重试意图及原上下文。复用 Empty、Skeleton、Hint、既有确认和反馈，不输出整段内部诊断到正常页面。
6. 重做验收：至少覆盖上述真实来源形态、插件禁用后仍可找到／重新启用、详情返回、混合批量选择、市场读取失败、版本限制和对应提示。测试应断言用户要求的行为，不能只断言当前限制。最后构建并检查所有新增／修改状态的设计一致性。

## 修正进度

用户随后明确批准 Agent 页面独立插件管理 Tab，替代原工具栏流程提议。已实施：移除设置空壳、正文管理行和技能卡片整包卸载；插件 Tab 单独搜索、选择、启停及合格来源卸载，技能批量只操作独立技能。详情更多菜单定位插件并保留返回入口。

canToggle 与 canUninstall／canInstall 分离，Git 市场启停通过原版 CLI 隔离测试；配置中存在而列表不可读的插件保留为“已配置”，不声称安装状态或扫描旧缓存。原生库存携带同一份 Codex 快照，插件页不另建 hook；缺失记录保留失败重试意图。Empty／LoadingCards／Hint 及紧凑确认替代原临时展示；保留版本限制并在受限插件开关提示。

尚不声称外部 Codex 会话实际热加载、远程目录完整浏览或远程插件安装／卸载。只有配置记录时不补造技能清单；插件管理入口仍保持可用。测试、构建与当前打包 UI 结果见[本轮验证](../specs/0010-codex-skill-plugin-management.md#最终范围与验收2026-10-21)。修正已完成，待用户复查；扩展 DSH 测试环境缺口单独记录，不宣称全套回归通过。
