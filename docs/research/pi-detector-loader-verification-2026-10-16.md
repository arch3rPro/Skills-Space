# Pi 技能检测与官方加载器对照

日期：2026-10-16。状态：五类检测修复已实施；项目信任显示保持原状。记录为本机隔离验证，不能推广为所有 Pi 版本／平台的保证。

## 比较口径

- 官方：本机发布包 `@earendil-works/pi-coding-agent@1.2.0` 的原版 `DefaultResourceLoader`、`SettingsManager`。
- App：[只读检测器](../../scripts/inspect-pi-skills.mjs)，已确认源文件与打包暂存文件一致；不引入 Pi 运行时依赖。
- 主验证：应用随附的官方 Node 22.20.0；修复前另用 Node 25.9.0 验证，60 项结果一致。
- 每例独立 HOME、Agent 根目录、项目、配置和本地包缓存；`PI_OFFLINE=1`、`noExtensions=true`，不调用模型、不执行扩展、不安装包、不读取真实 Pi 配置。信任通过隔离 SettingsManager 显式设置。
- 比较 `(name, canonical file path, manual invocation)`。App 仅取 `enabled && reason !== 'shadowed'`；额外保留的停用／覆盖管理记录不算差异。`globalInProject` 表示当前范围不可编辑，不等于未加载。

## 差异与处理

| 类别 | 最小反例 | 修复前 | 官方与修复后 |
| --- | --- | --- | --- |
| 包清单空数组 | 包声明 `pi.skills: []`，配置为 `{source:'./pkg'}` | 回退扫描包内默认目录 | 不加载；仍保留用户显式筛选触发约定目录回退的原生语义 |
| Git 包身份 | 全局 `git:https://github.com/fixture/repo`、项目 `https://github.com/fixture/repo` | 两份包同时有效 | 按 Git host/path 识别同一包，项目覆盖全局；npm 身份仍去除版本 |
| 同级发现顺序 | `skills/B`、`skills/a` 声明同名技能 | 英文 locale 排序改变获胜者 | 跟随 Pi 的文件系统枚举顺序；包清单 glob 另保留 Pi 的字典序 |
| 有效性校验 | 缺少、空白或非字符串 description；项目无效同名技能覆盖全局有效技能 | 无效项仍启用并占名 | 忽略无效技能并记录诊断；全局有效项可正常生效 |
| 空名称 | `name: ""`，文件位于 `skills/alpha/SKILL.md` | 名称为空 | 回退目录名 `alpha` |
| 信任状态（暂不处理） | SettingsManager.projectTrusted=false，项目有技能 | App 仍呈现配置启用 | 官方不加载项目资源；本次按用户要求保留差异，不隐式授予信任 |

同级 `B/a` 是本机可复现反例，不宣称所有文件系统固定由 B 获胜；正确合同是跟随同版本官方枚举语义。

## 项目安装归属补充修复 — 2026-10-17

SelfGuard 无 Git 边界时复现：父目录扫描到 HOME 后，原检测器先用项目配置登记全局共享技能，随后全局扫描因去重跳过，造成全局安装被展示为项目托管技能，并缺失项目来源记录。对照 Pi 1.2.0 `package-manager.js` 发现官方祖先扫描会排除用户共享根，再用用户规则加载；现补齐这一排除，恢复全局过滤规则与优先级。

新增独立 `inScope` 表示当前库存归属，不替换加载／配置的 `scope`。父目录继承仍参与加载和同名判断；Rust 库存仅合并 `inScope` 的记录，CLI 可操作性仅匹配当前范围的共享根，继承目录不允许移至废纸篓。项目内真实存在、指向全局内容的链接仍属于项目安装；显式项目配置与扩展包仍按配置所有者归属。

针对性官方对照分别使用本机原版 Pi 1.2.0 和 1.3.0、隔离 HOME、可信项目、离线且禁用扩展执行，比较启用且未被覆盖技能的 `(name, canonical file path)`。无 Git 项目、父仓库同名覆盖、项目链接、全局排除规则共 4 类、两个版本合计 8 例全部一致。原来的 60 例临时目录已不存在，本次未重跑 60 例，也未改变项目信任显示的既有边界。临时对照脚本为 `.scratch/pi-ownership/compare.mjs`，不纳入版本控制。

最终针对性检查：Pi TypeScript 测试 4/4、脚本／调用测试 17/17；Pi 原生测试 10/10（含原版 CLI copy/link 安装、启停和卸载），本地废纸篓保护测试 5/5。真实 SelfGuard 只读检测仍保留 25 个加载候选，当前项目归属为 0；之前混入的 7 个共享技能均为全局、非本项目 CLI 目标。真实技能内容与配置未修改。
