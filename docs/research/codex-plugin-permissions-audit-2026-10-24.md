# Codex 插件权限与接入能力核查（2026-10-24）

状态：原始研究与批准后实施记录；前文为实施前快照，最新实现及验证见文末进展。本轮已修改适配判定与展示代码，未改变真实账号插件权限。范围为 Skills Space 的 Codex 插件管理，以及其关联技能、市场、MCP 与账号状态的边界。本文不是已交付能力声明。

## 结论与证据边界

当前实现确实混用了“官方授权”“当前接口能力”“项目接入完成度”“状态读取是否成功”。现有 `canInstall/canToggle/canUninstall/canCheckUpdates` 只能解释本项目此刻能否执行，不能用来声称官方是否允许。界面存在因来源标签、策略来源和配置层过度归类的风险。

本机只读确认原版 `codex-cli 0.162.1`。源码判断固定到该版本提交 `092d3acd6bec3e3a14bdc7e7a2810ab628ab759d`；在线官方文档按本次读取结果记录。两者出现差异时分别保留，不将新文档描述倒灌成旧版本已具备的能力，也不将旧版本缺口当作永久限制。真实 App 的远程开关可用由用户反馈提供，未在本次擅自切换真实插件验证。

特别更正：官方文档和 TUI 确实提供插件启停入口；固定版本 TUI 的 `write_plugin_enabled` 使用 `config/value/write`。但该版本远程加载时使用远程安装记录的状态覆盖本地插件配置，仅保留本地 MCP server 策略；配置处理器的写入链路清理缓存、发送统计事件，并不能据此证明它更新了远程安装状态。因此应标记“官方支持；当前版本的第三方生效链路待核验”，既不能宣称不可能实现，也不能只放开开关后宣称成功。

## 必须分开的六层判定

| 层级 | 需要回答的问题 | 正确边界 |
| --- | --- | --- |
| 官方产品行为 | App、CLI 各自是否提供该操作？ | App 有不等于无交互 CLI 有，也不等于第三方接口稳定 |
| 插件与工作区策略 | 谁安装、是否强制、谁能改变、操作影响哪个范围？ | `AVAILABLE/NOT_AVAILABLE/INSTALLED_BY_DEFAULT` 与策略来源分别记录；逐操作解释 |
| 身份与服务授权 | 当前账号、工作区、角色、连接状态能否完成动作？ | 未连接 GitHub 与插件不能停用不是同一含义；安装认证与调用认证也不同 |
| 接口能力 | 当前运行程序是否有公开接口？是否为实验接口？ | 无 `enable` 子命令不等于无配置写入能力；实验接口存在不等于可投产 |
| 本项目接入 | 处理器、确认、执行、读回、失败恢复是否完整？ | “尚未接入”“尚未验证”不写成官方禁止 |
| 观测与运行状态 | 状态是否新鲜、已生效到何处？ | 读取失败不是权限被撤销；配置写入成功不证明已运行会话重新加载 |

## 操作矩阵

“可实现”表示存在可采用的公开路径或可明确补齐的适配；不表示本次已授权实施或真实账号已验收。

| 对象／操作 | 官方行为及约束 | 项目现状 | 可行性与下一步 |
| --- | --- | --- | --- |
| 已配置本地市场：查看／安装／卸载 | 原版 `plugin list/add/remove`；最终策略仍由原版处理 | 已接入 | 可沿现有路径；逐操作复核策略，不按内置名称封禁 |
| Git 市场：查看／安装／卸载 | 原版市场解析及插件命令 | 已接入受支持范围 | 支持范围应注明协议／凭据边界，不能概括成“Git 插件不支持” |
| 本地市场插件：全局启停 | 原生配置写入；有效配置及要求决定生效 | 已接入；移除了详情管理页重复开关，列表／批量仍有 | 可实现；修正把任意非 user 层等同强制限制的判定 |
| 本地市场插件：项目启停 | 官方支持可信项目 `.codex/config.toml` | 本项目当前只写用户层，未提供项目专属插件开关 | 可实现但属于待扩展范围；明确用户级与项目级，不声称官方不支持 |
| GitHub、Writing Style：查看／安装／卸载 | 当前原版 CLI 有远程生命周期分支；服务校验身份和策略 | 已接入库存及安装／卸载；真实账号变更未作为本次测试 | 可实现；保持原版 CLI 执行和读回 |
| GitHub、Writing Style：启停 | 官方 App 有开关，文档描述 CLI 插件浏览器可启停 | `catalog.rs` 把所有 remote 的 `canToggle` 直接设为 false | 官方支持明确；自动化接入生效链路尚未核验。优先核对当前版本实现及生效状态，再决定配置接口或官方原生交接 |
| 工作区／默认插件：卸载 | 官方说明这些插件可能不提供卸载；受实际策略控制 | 仅 `AVAILABLE` 可卸载；其余一律显示默认安装限制 | “默认提供”不等于其他动作禁止；缺失／未知策略不能伪装成默认安装。远程服务明确拒绝时再归类官方限制 |
| 内置／运行时插件：启停 | 来源本身不构成统一禁用条件 | 没有按 `builtin` 一刀切，但仍受粗配置层判断影响 | 逐对象逐操作；不要用 `builtin` 决定整包可管理性 |
| 本地／Git 插件：检查来源变化 | 项目采用只读来源快照比较，不是官方独立 check-update 命令 | 已实现；mattpocock 旧格式及源码链接问题已修复 | 可实现，分别标明当前内容／来源内容／错误；有网络错误不能说无权限 |
| 本地／Git 插件：整包更新 | 当前采用原版安装流程及配置保留，而非独立官方单插件 update 命令 | 已实现；依赖可启停、可卸载、可安装 | 这些是现有更新流程所需步骤，不是官方“更新权限”。某一步不支持时应说明流程限制，而非断言官方不能更新 |
| 远程插件：版本／内容更新 | 产品缓存同步、目录版本与本地包版本是不同事实 | `canCheckUpdates=false`；未接独立远程检查／更新 | 尚未接入／尚未确认公开只读路径；不能写成“远程插件不可更新”，也不能用卸载重装冒充检查 |
| 市场：添加／列表／移除 | 原版 `plugin marketplace add/list/remove` | 已接入用户市场 | 移除市场不等于卸载插件。项目／系统注册不能伪装为用户注册项移除 |
| Git 市场：升级 | 原版 `marketplace upgrade`；可能刷新该市场已配置插件的缓存，含停用项 | 只有研究，未加操作入口 | 有明确公开路径，可实现；前次未授权实施，不是官方不可用。不能将它替换为只读刷新按钮 |
| 插件内单技能：启停 | 有 `skills/config/write`；受作用域、管理员技能及插件状态影响 | 已接用户级规则；插件关闭时保留技能自身设置 | 独立于整包开关；技能 enabled 不等于所属插件整体已生效 |
| 插件内 MCP：启停／工具审批 | 官方有插件级 server 配置和工具策略 | 本项目未提供编辑面板 | 有公开配置路径，技术可行；属于额外产品范围，不应把缺少面板描述成无权限 |
| 服务连接／OAuth | 插件可能在安装或使用时要求连接；工作区和角色也可能限制 | 只展示有限认证说明，未接完整连接管理 | 需独立核查服务对应的官方流程；不能用安装成功推断服务已连接，不能用断开服务代替停用插件 |
| Hook 信任／工具调用审批 | 安装、启用、脚本可执行、审批和 OS 权限各自独立 | 当前插件页不是完整运行权限管理器 | 单独记录未接入项；不随本次权限梳理自动增设设置页 |

## 已定位的判定偏差

以下是当前代码证据。标记为“需验证”的项目表示规则过粗或证据不足，不等于已经证明每一条真实插件被错误禁用。

| 编号 | 当前位置与规则 | 问题 | 应调整的语义 |
| --- | --- | --- | --- |
| P01 | `src-tauri/src/upstream/codex/catalog.rs:48`：`can_toggle` 必须是 local source | 远程类型直接变成禁用，官方支持与接入缺口混合 | remote 是路由信息；启停单独记录官方支持、接入和核验状态 |
| P02 | `codex.rs:439`：`installPolicySource` 非 null 直接否定 `policy_allows` | 策略来源并非通用的禁止所有操作标志 | 结合具体策略、操作和有效配置；记录未知而非推定禁止 |
| P03 | `codex.rs:441`、`catalog.rs:44`：任意非 user 层出现 enabled 都视为覆盖 | 低优先级默认值、可信项目覆盖、强制要求未分开 | 按实际优先级和要求判断“不可写”或“可写但当前范围不生效” |
| P04 | `codex.rs:467–471`：同一配置覆盖条件还禁止安装／卸载 | 启停配置覆盖并不自动证明安装或卸载均被官方禁止 | 生命周期操作单独核对策略、影响范围和原版执行资格 |
| P05 | `catalog.rs:43/71` 与 `codex.rs:475`：非 AVAILABLE 统一解释默认安装 | 未知、缺失、NOT_AVAILABLE 与默认安装容易被同一句话覆盖 | 明确默认提供、策略不允许、策略未知；不制造原因 |
| P06 | `capabilities.rs`：通过 help/schema 推断能力，结果缓存于二进制身份 | 它探测接口形状，不能证明当前账号／工作区／插件获准；缺字段也可能是版本差异 | 接口能力与对象授权分开，服务错误归因保留 |
| P07 | `updates.rs:223–226`：更新资格依赖 toggle/uninstall/install | 自有更新步骤依赖被当成更新能力本身 | 明确“现有更新流程未覆盖此类对象”；不从中推导官方禁止更新 |
| P08 | `src/lib/codex.ts:60/132`：可管理为四个执行 boolean 的 OR；可安装集合必须 canInstall | 尚未接入对象可能被隐藏／从可安装筛选排除 | “官方允许安装”与“本项目可执行安装”分离；未接入不应自动消失 |
| P09 | `codex.ts:163–173`：未知 reason 默认解释接口不支持 | 未知原因被制造为具体限制，`policy` 又合并配置与管理员 | 未知保持未知，读取错误保持错误；展示具体动作原因 |
| P10 | `catalog.rs` 已安装目录合并只请求 installed，并清空 available | 远程“可安装”不是完整官方目录 | 该筛选只是当前已读取范围，不能声称覆盖官方所有可安装插件 |
| P11 | 原生技能写入为用户层；市场只接公开 HTTP(S) 或本地 | 当前产品范围／适配选择并非官方权限边界 | 标注项目尚未接入的作用域、协议和认证流程 |
| P12 | metadata、图标、版本、内容可读性与执行资格 | 展示／检查失败不能推导安装或启停权限不存在 | 保持具体失败可重试，不永久封禁核心操作 |

## 建议采用的状态表达

按每个操作保存几项独立事实，先在现有对象上最小扩展，不新建一套权限服务：

- 官方支持：支持／不支持／证据不足，附版本及证据。
- 目标策略：允许／明确禁止／未知，附约束来源与生效范围。
- 接入状态：已接入／待接入／待验证／该接口版本不支持。
- 观测状态：已确认／过期／读取失败；认证需要另外说明。
- 现有 `can*` 继续作为最终按钮能否执行的派生结果，不能反向充当官方权限事实。

用户侧按动作说明：`受工作区策略限制`、`当前项目覆盖用户设置`、`需连接服务`、`此操作尚未接入`、`状态读取失败，请重试`。官方限制与项目未实现不能继续统称“不可管理”。

“隐藏不可管理插件”应重新明确：建议仅隐藏已确认没有相关用户操作的对象；尚未接入、未知、读取失败另作说明，不与官方禁用混在一起。具体筛选文案及布局在实现时沿已批准设计基线处理。

## 具体执行顺序与验收

1. 先纠正状态来源与归因：P02–P06、P08–P10。每条真实限制保留证据，未知不猜测。不得为了消除置灰而默认放开所有操作。
2. 远程启停单独补链路验证：比较当前 App 行为、固定 CLI/TUI 的写入参数、有效状态来源、原生读取、新进程与运行时加载；覆盖 GitHub 和 Writing Style、用户安装与工作区／默认策略。真实账号变更只在明确授权后执行；可先用模拟服务和隔离 HOME 验证。
3. 已有本地生命周期／更新流程复核：配置优先级、默认策略、未知字段、不同来源格式、插件内规则保留、多个项目影响，不回退为直接编辑插件缓存。
4. 有公开路径但尚未批准的功能分别列出：项目插件启停、完整远程目录、市场升级、MCP 设置／服务连接。按用户选择推进，不以本次研究自动扩大功能。
5. 每个可执行操作都验收“原生执行 → 原生安装／策略状态读回 → 对应运行时效果”；配置写入、安装事实和会话重新加载不能互相替代。

本轮只读核查及文档整理，不需要运行构建；没有测试新的权限修改，也没有宣称远程启停已实现。

## 批准后的实施进展（2026-10-24）

用户批准先修正权限判定、筛选及提示，再验证远程启停。前文为实施前快照；本节和 spec 0010 的同日记录描述实际变更。

已修正 P02–P05、P08–P09 对应的逐操作判定与展示：新增操作状态、保留原始策略、按配置优先级判断覆盖、移除安装/卸载与项目 enabled 覆盖的错误耦合、默认安装缺少策略来源时保持未知。未知或接入缺口不再被受限筛选隐藏；未知 reason 不再默认翻译为接口不支持。卡片不再展示无执行链路的置灰按钮及实现限制 Tooltip。

远程启停仍未交付为应用可执行操作：本机原版 CLI 0.162.1 分别以仅本次调用的 `plugins."github@openai-curated-remote".enabled=false/true` 和 Writing Style 同项配置覆盖读取安装列表，两次均返回原生 enabled=true，策略 AVAILABLE。GitHub 的 authPolicy 为 ON_INSTALL，Writing Style 为 ON_USE。没有写配置或改变账号安装状态。该结果说明本地覆盖不能用作远程状态更新的成功证据，并非官方产品不支持启停。原生 TUI 写入/配置处理/远程合并源码链路与上述现象一致；不能只放开 Switch 或以卸载替代停用。

计算机工具明确禁止访问 `com.openai.codex`，因此本轮无法自动切换官方 App 的真实开关；未改用其他 UI 自动化手段绕过。已请求用户在方便时手动切换以完成 App/CLI 对照。其他实现与隔离验收独立推进。
