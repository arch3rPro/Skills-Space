# Codex 增强收敛方案（B2—B4 已实施，待用户验收）

日期：2026-10-22。依据：[累计改动清单](codex-change-inventory-2026-10-22.md)、用户已确认范围、当前代码及[分批记录](codex-implementation-reconciliation-2026-10-22.md)。初版仅整理方案；用户随后分别批准执行 B2、B3、B4，结果见本文末尾。其他批次不因此获得授权，不改设计基线、不提交。

## 一、收敛结论

保留本地技能、规则、本地插件、已批准的更新能力；减少重复入口、日常技术提示、全库存重读、无关冲突和额外操作门槛。复杂的内部保护尽量不让用户学习，也不能仅藏起来而保留错误阻断。

不将“已批准但没实现”归为多余功能。独立技能启停、名称/路径规则、恢复继承、内容指纹、整包更新、状态保留及路径迁移均不能直接撤掉。远程插件按需读取也已经确认，继续与本地管理分开。

分类：**保留**是必要能力或已确认要求；**简化**保持结果，缩小实现/展示/校验；**撤掉追加**是不必要且未经确认的产品扩展或错误替代；**待决定**是会改变已确认能力的取舍。本方案中 B2 已获准实施；其他批次仍按各自授权执行。

## 三、校验逐条减负

原则：只在即将写入/覆盖时检查与当前动作有关的事实。后台自动检查不是额外授权步骤；没发现冲突时不让用户确认、刷新或重新检查。缺辅助证据不等于真实冲突。

| 校验/限制 | 当前代码事实 | 建议 | 少做后的影响与必要底线 |
| --- | --- | --- | --- |
| 云端账户/工作区核验 | 本地依赖已在 B1 撤掉 | 保持撤掉，不复活 | 无法证明桌面会话云端身份，但本地技能/插件管理无需它 |
| 每次动作扫整份库存 | toggle 先 inspect，再读取配置和技能，写后读技能，最后又 inspect；save_rules 前后 inspect | 只读目标技能/规则；复用同一操作会话；完成后按需刷新相关视图 | 减少重复请求；仍要确认目标和写入结果，不能只返回成功 |
| 所有操作都比整份配置 revision | plugin_apply 对安装/卸载/启停共用前置版本比较 | 安装/卸载去掉无关配置版本门槛；配置写入仍用原生 expectedVersion | 原生命令自己管理安装记录；写配置不能无版本保护 |
| 无关配置变化强制重做 | 任何 revision 变化都拒绝 | 最新配置中目标字段/有序规则语义不变时，保留外部变化并以新版本写入；目标本身变了才报冲突 | 只作一次有界重新读取，不循环重试；不能擅自合并相互影响的名称/路径规则 |
| 插件整条记录 fingerprint 相等 | 插件操作比较记录签名；远程签名包含序列化条目，不等于内容 hash | 按动作比较身份、安装路径和有影响的策略/组件；描述、作者等无关变化不阻断启停 | 安装目标变了、更新内容变了仍需重新确认 |
| 更新检查结果整体相等 | update 使用 actual != reviewed | 比较目标、候选内容、需覆盖的当前内容、受影响规则；排除无关 revision/展示字段/辅助状态 | 保证安装的是审核候选，不因无关设置变化反复检查 |
| 缺历史基线 | check 将 localState 标为 unknown，当前不一定直接禁止更新；坏记录读取会报错 | 不新增缺历史阻断；可选基线损坏与有效恢复记录分开处理 | 无基线不能断言“用户修改过”；仍可比较当前与来源，使用已有覆盖确认 |
| 整包启停后的技能列表要求 | 停用验证还检查没有 enabled 技能 | 区分单技能配置选择与整包有效状态，按原生契约验证整体停用，不要求把子技能规则全改 false | 保持用户单技能选择；必须避免整包已停但页面错误宣称子技能实际生效 |
| 卸载后所有目录必须消失 | 当前核验包含 installed_path 不存在、无所属技能 | 原生安装记录移除为主体；缓存残留单独识别，不当作安装仍在。实际活跃安装未移除仍失败 | 不能把有缓存误认为卸载失败；也不能仅凭命令退出码报成功 |
| 内置/管理员标签一律禁止规则 | 规则/技能代码存在按 scope/origin 只读限制 | 真正只读政策保留；仅凭“内置”推断不可管理的限制需按本地原生接口逐项验证后删除 | 不能未经证据开放管理员策略写入，也不能把未接入说成官方禁止 |
| 插件停用/技能未载入不许单独设置 | 当前依赖 skills/list 中 can_toggle 等条件 | 允许配置层独立选择，整体是否生效另算；以已有真实技能身份和用户规则读回核验 | 不需要先开整包再关单个技能；不能虚构“已在当前会话生效” |
| 技能删除/改名时路径迁移直接拒绝 | migrate_rules 对候选缺旧路径直接返回错误 | 同路径自动迁移；消失路径不猜新目标、不删原规则。真实冲突在现有更新确认中列出对象，由用户决定继续或取消 | 这是会影响“所有状态均自动保留”含义的例外，执行前单独确认，不能静默降级 |
| 读取超时/响应大小/路径合法性 | 通信及文件处理有边界限制 | 保留合理技术边界，避免重复扫描；超限不变成永久管理资格 | 这类检查没有用户额外步骤，防卡死、错路径和资源失控，不应全部删除 |
| 更新临时恢复记录 | 用于多步安装/配置恢复 | 保留本次事务最小数据，成功后清理待恢复状态，不加恢复中心/诊断面板 | 删除它会失去已批准的中断后状态恢复；不能算无意义存储 |

**不保留的通用门槛**：登录云端才能本地管理；先查完整目录才能改一个本地项；无历史基线就不许更新；缺图标/作者就不许卸载；任何无关字段变化都要求重新确认；因缓存目录还在就认定卸载失败。这些是方案中的禁止条件，不声称当前代码已全部存在或全部修复。

## 四、三条精简后的处理链

1. **技能开关**：确定目标及相关规则 → 带原生版本保护写入用户规则 → 读回该规则及可获取的有效状态 → 更新当前卡片。正常单项不新增预检页；插件停用不抹掉单技能选择。
2. **插件启停/卸载**：确认目标安装事实和动作权限 → 按原有必要确认执行原版接口 → 读回目标状态。介绍缺失、无更新基线、其他远程插件失败不参与阻断。
3. **插件检查/更新**：检查真实来源且不安装 → 有变化时按原更新弹窗展示对象、版本/内容变化和整包影响 → 核对候选未变，保存最小恢复信息 → 原版整包更新 → 恢复该插件及其技能规则 → 读回结果。没有变化走短反馈，不在每张卡片留检查状态串。

上述是调用范围约束，不承诺每条链只有一次进程启动或固定 RPC 数量；由原生接口决定必要请求，不为凑次数删核验。

## 五、建议实施顺序与验收

沿用 B1–B6，不另建一套修复批次。本方案不是进入后续批次的授权。

| 顺序 | 批次/内容 | 交付要求 |
| --- | --- | --- |
| 1 | B2：技能/规则与对应界面；同步其局部加载 | 单技能/批量/插件停用场景正确；恢复继承正确；不扫远程或无关插件；无“未载入”替代功能；名称/图标一致 |
| 2 | B3：本地插件生命周期及必要确认 | 本地安装、启停、卸载、刷新/重启闭合；缺展示元数据可管理；缓存残留不误报；远程失败不阻断本地 |
| 3 | B4：真实来源更新与最小恢复 | 检查无安装副作用；审核候选等于安装候选；状态和规则保留；无历史基线可用；真正冲突处理明确 |
| 4 | B5：跨页面重复请求和加载 | 真实规模全局/项目读取、详情、操作前后计数计时；只按对象使检查结果失效；不加长期存储换性能 |
| 5 | B6：跨页面收尾及文档一致 | 无重复入口、常驻正常提示、占位功能；共享组件及失败状态符合原基线；有效文档与实际能力一致 |

每批自己完成涉及界面的简化和验证，不能把当前界面问题都推到 B6。只有对应功能实际可用、失败可处理、构建通过才能关闭；撤掉提示不算完成。

## 六、需要用户决定、目前不执行的取舍

- **是否进一步削减已批准功能**：若希望暂停 Git 远端更新、整包更新、规则高级编辑或远程生命周期，需要具体批准；本方案默认保留，不以“本地为主”自行取消。
- **更新后技能删除/改名**：建议只有无法自动对应的条目进入已有更新确认，允许明确继续时保留未映射旧规则，不猜测映射、不静默删除；用户于 2026-10-23 明确确认，纳入 B4 实现。
- **其他平台 App-only**：macOS 已接入，Windows 尚未实现。继续标明范围，不擅自扩展本机验证结论；是否纳入本轮交付需另定。

常驻信息提示、运行诊断区、技术筛选、重复全库存检查等纠偏可与原批次一起处理；不需要为每个删除单独再问，但执行整批仍等待本方案核对。


## B2 执行结果（2026-10-22）

本批保留技能单项/批量启停、名称/路径规则、顺序、移除覆盖恢复继承、草稿保护、显示名称、自身图标、来源、插件版本及内容指纹。去除设置页运行路径/版本诊断区、名称规则匹配数量、技能“未载入”日常筛选和无依据的“未提供”版本行。普通启停不再仅因存在名称规则另加确认；真实项目/共享路径影响仍沿用原确认。

- 插件开关控制整包；技能开关保存自身设置。插件停用时仍可调整技能，重新启用不覆盖其选择。内置技能可使用原版用户规则启停；管理员来源仍保持只读。
