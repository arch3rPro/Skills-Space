## 阅读方式

“原版支持”和“推荐放在 Agent 管理”是两个独立判断。表中的“不放此页”不是“不能实现”。

- **推荐·常规**：适合作为 Codex Agent 设置的直接内容。
- **推荐·高级**：真实可配，但范围较大或偏专业，折叠在高级区域，默认保持继承。
- **详情/专页**：可管理，放在具体技能、插件、连接器、Hook 或市场页面；Agent 设置只保留入口。
- **只读/内部**：有展示或执行用途，但不提供自由编辑框。
- **暂不产品化**：当前入口的持久性、宿主作用范围或实际执行效果尚未闭环；不放占位或置灰按钮。

验证标记：**行为**=隔离原版读到实际效果；**读写**=类型接收、原版保存及配置读回；**定义**=官方字段/协议明确，但没有完成该项运行测试；**已有**=项目已接入，具体边界见前轮记录；**静态**=当前 App 安装包代码。验证“读写”不等于真实服务调用已全部验证。

以下键名中的 `<plugin>` 指原版完整插件 ID，通常为 `插件名@市场名`；`<app>` 是原版连接器 ID；`<server>`/`<tool>` 是原始服务/工具名，不是中文显示名。用户路径展示为 `~`，执行和保存使用原版需要的绝对路径。

## 共同的影响范围和生效规则

1. **用户配置**通常影响使用同一 `CODEX_HOME` 和相应配置方案的 Codex 环境，不等于机器上所有 Agent，也不等于账号全局。其他配置根/方案不保证同步。
2. **项目覆盖**只在原版实际读取的可信项目配置层中成立；字段能写进项目文件不证明运行时使用它。本轮技能启停规则在项目层未生效，插件项目覆盖则有独立证据和实现。
3. **账号操作**作用于服务端账号/工作区及其允许的范围。安装、连接授权、工具审批、本地工具可见性各有含义，不能互相代替。
4. **运行期接口**只影响对应进程/宿主会话；给我们启动的独立 App Server 写状态，不等于改变官方 App 正在运行的会话。
5. **技能/插件文件**属于内容来源。修改会影响该文件的其他引用者，更新也可能替换它；个人设置不能通过静默改缓存实现。
6. **恢复继承**删除当前显式覆盖，不是写入 `true`，也不保证最终启用。上层策略、来源状态、其他匹配规则仍可能限制它。
7. **生效时机**以原版重载/读回为准；没有宿主热更新证据时，不承诺已改变官方 App 当前会话。管理员要求不能由用户默认项解除。
8. **产品默认建议**统一为继承当前原版有效策略；接入新字段时不主动新增显式值。下表明确标注有证据的默认值，未确定的值不猜测。

## 五、Hook 定义、启停与信任

Hook 与工具调用审批不同：启用 Hook 不代表其定义已被信任；信任记录也不代替来源的启停和管理员要求。普通用户 Hook 的状态读回已测试，插件脚本内容信任和实际执行没有据此宣称通过。

| 编号 / 设置项 | 功能与默认/继承 | 影响范围 | 注意事项 | Agent 管理建议 / 推荐值 | 验证 |
| --- | --- | --- | --- | --- | --- |
| H01 `hooks.state.<key>.enabled` | 对一个非受管理 Hook 保存启停覆盖；缺省按原版/来源状态 | 指定 Hook，而非全部插件 | 管理员 Hook 不能据此关闭；启用但未信任仍可能跳过执行 | Hook 专页，Agent 设置提供入口；默认继承 | 类型识别、普通 Hook 读回 |
| H02 同 Hook `trusted_hash` | 记录用户审阅过的当前定义哈希 | 精确 Hook 定义 | 定义变化后须重新审阅；用户不应手填任意字符串或自动信任所有 Hook | 专页“审阅并信任”动作的内部字段，不做文本设置框 | 普通用户 Hook 行为 |
| H03 同 Hook `trusted_content_hash` | 与定义声明分开记录已批准的插件内容 | 插件贡献的 Hook 内容匹配 | 不能从 H02 的测试推断插件脚本改动已被正确检出；更新后的旧信任不能盲目沿用 | 只读/内部，插件 Hook 差分验证后才提供对应信任动作 | 定义；内容变更未验 |
| H04 `hooks.<Event>[]`、matcher、handler | 声明事件、匹配条件及 command/MCP 工具处理器；可来自 TOML 或 hooks.json | 用户、可信项目、插件或受管理来源的生命周期 | 多个来源会累计，不简单按高层替换；同层混合文件/TOML会合并并警告。当前 prompt/agent handler 是解析但跳过，不能当成可用处理器 | 编写/导入属于 Hook 专页，不将事件数组摊在 Agent 常规设置 | 定义 |
| H05 handler `timeout` | 限制该 Hook 处理器等待时间；未设按原版事件/handler 默认 | 指定 Hook 的执行等待 | 过小可能让必要 Hook 超时；不是所有 Agent 的启动超时；实际命令执行本轮未验 | Hook 编辑详情·高级，默认保持来源值 | 定义 |
| H06 handler `async` | command Hook 是否后台运行，默认 false | 该事件处理器是否阻塞触发操作 | SessionEnd 仍同步；异步可能改变结果可用时机，不是无损的通用提速开关 | Hook 编辑详情·高级，默认保留作者/来源值 | 定义 |
| H07 handler `additionalContextLimit` | 控制 Hook 附加上下文超过阈值时转存文件；未设约 2500 tokens，0 禁止该转存 | 该 Hook 的附加上下文传递 | 不是丢弃所有超限内容或模型总上下文上限；设置过大可增加提示词体积 | Hook 编辑详情·高级，默认继承/来源值 | 定义 |
| H08 handler `statusMessage` | 提供执行时的状态文字；可选 | 该 Hook 在支持宿主中的执行展示 | 不是运行权限；不应把输出或凭据直接拼进状态文本 | Hook 创作元数据，不放 Agent 常规设置 | 定义 |
| H09 `hooks/list` 来源、事件、管理标记、信任状态 | 只读说明哪个 Hook 来自哪里，是否受管理以及是否变更 | 当前实际读取的 Hook 集合 | 这些不是用户配置开关；管理策略来源须保留，不提供绕过按钮 | 推荐到 Hook 专页，来源和限制在详情说明 | 行为、原版协议 |

来源：[官方 Hook 文档](https://learn.chatgpt.com/docs/hooks)、本机生成的 HooksListResponse 及普通用户 Hook 隔离读回。管理员 Hook、项目可信条件和插件内容信任分别处理。

| C03 同服务 `env` / `http_headers` | 服务进程环境或 HTTP 静态头 | 一个服务进程/HTTP 连接 | 可能含敏感值，禁止默认读取/展示现有值；本项目凭据存储要求与原版明文配置入口须另行设计 | 不进入普通 Agent 表单；只有明确新增连接方案后处理 | 定义；敏感接入未设计 |
| C04 同服务 `env_vars` / `env_http_headers` / `bearer_token_env_var` | 声明传递哪些变量或从哪个变量取认证材料 | 该服务所需的环境引用 | 变量名不是实际授权；不为“检查连接”向模型或日志输出已有变量值 | MCP 专页按引用管理；不读取现有凭据 | 定义 |
| C05 同服务 `enabled`、工具列表、审批和输出预算 | 控制该独立服务及其工具；字段含义可参照 P05–P10，但键根不同 | 一个独立服务/工具 | 不能把独立服务和插件服务合并存储；每个具体字段按实际 schema 匹配 | MCP 专页/工具详情，默认继承原策略 | 定义；与插件字段分别验收 |
| C06 同服务 `startup_timeout_sec` / `startup_timeout_ms` / `tool_timeout_sec` | 分别限制服务启动或工具调用等待；两个启动超时字段是单位不同的别名 | 一个 MCP 连接/调用 | 不靠缩短超时掩盖失败；不是 Skills Space 插件发现速度设置 | MCP 详情·高级，默认继承，不同时创建冲突别名 | 定义 |
| C07 `mcp_optional_startup_grace_ms` | 可选 MCP 启动时用于构建初始工具目录的共享等待；schema 默认 1000ms，0 的含义是改为等待各服务配置超时 | 当前运行时可选 MCP 的初始目录 | 0 不是“完全不等待”；不保证解决本应用清单扫描/网络发现延迟 | 不推荐普通 Agent 设置；有启动问题时专项调优 | 定义；实际启动未验 |
| C08 同服务 `startup_readiness` | connection 要求连接就绪，catalog 允许有效工具目录缓存先就绪；缺省由原版策略决定 | 一个 MCP 服务初始工具暴露 | 执行仍需要实际连接；不等于断网也能正常调用，不是我们清单缓存策略 | 暂不优先产品化，先验实际客户端/版本 | 定义；当前执行效果未验 |
| C09 OAuth 客户端、回调、scope 与凭据存储选项 | 配置该独立服务的授权方式；登录/注册动作另走原版授权 | 特定 MCP 的新授权连接 | 不是 Codex 账号登录设置；不读取/复制现有 token；新凭据处理须遵循 OS 安全存储要求，不能直接照抄原版明文 client_secret 编辑框 | 只在获准的独立 MCP 连接流程中设计，不放全局 Agent 常规页 | 定义；本轮未授权实际服务 |
| C10 同服务 `required` | true 时，已启用服务初始化失败可阻止启动/恢复流程 | 当前会话的启动/恢复可用性 | 这是严格依赖语义，不是提高服务优先级；错误设置会放大单服务故障影响 | MCP 详情·高级，默认继承原版，不自动设为 true | 定义 |
| C11 同服务 `omit_tools_from` / `tool_input_schema_max_bytes` / `supports_parallel_tool_calls` | 控制工具暴露通道、schema 精简阈值或并行调用能力声明 | 该服务的模型接口/调度 | 不改变账号服务权限；并行能力不能由用户随意宣称为真，schema 精简也不是无损提速 | 不推荐普通 Agent 设置；有版本及服务证据后专项调优 | 定义；运行效果未验 |

本节依据[官方 MCP 文档](https://learn.chatgpt.com/docs/extend/mcp)与原版配置 schema。仅为了清楚区分独立服务和插件服务；不把“真实支持”直接变为本轮新增功能授权。

## 九、管理员约束与项目可信状态

这是会改变实际权限的来源信息，不是一组让普通用户解除限制的配置开关。只在当前能力确实受影响、且原版可提供证据时说明来源；不把所有限制做成置灰按钮。

| 编号 / 项目 | 功能与默认/继承 | 影响范围 | 注意事项 | Agent 管理建议 / 推荐值 | 验证 |
| --- | --- | --- | --- | --- | --- |
| R01 requirements 的市场来源限制 | `marketplaces.restrict_to_allowed_sources` 激活来源允许规则；`allowed_sources` 可按本地目录、Git 仓库/ref 或 host_pattern 匹配 | 添加市场、安装、刷新及运行时允许的市场来源 | 不等于单插件启停；内置和工作区远程插件还存在各自策略；用户本地 true 不能解除强制要求 | 只读解释实际限制；普通 Agent 设置不编辑管理员文件 | 官方要求定义 |
| R02 requirements 的插件 MCP 身份允许规则 | `plugins.<plugin>.mcp_servers` 限定允许服务；identity 按 command/参数或 URL 匹配 | 插件贡献的 MCP 服务 | 表存在时没有匹配项的服务可被禁用；名称匹配不等于服务身份匹配；这不是普通服务 URL 编辑器 | 插件服务详情只读展示必要原因，保留原版执行结果 | 官方要求定义 |
| R03 requirements 的 app/工具约束 | 可强制关闭 app 或限制单工具审批模式 | 对应连接器及工具 | 同名键放在 requirements 与用户 config 中，权威和可改性不同；用户允许不解除管理员拒绝 | 只读展示，账号与工具详情解释实际来源 | 官方要求定义 |
| R04 `allow_managed_hooks_only` | true 时跳过用户、项目、会话、插件 Hook，仍允许受管理 Hook | 当前受管运行环境的 Hook 来源 | 对普通 Hook 再写 enabled/trusted_hash 不能使其绕过限制 | Hook 专页只读原因，不提供“强制启用”按钮 | 官方要求定义 |
| R05 `projects.<path>.trust_level` | 用户配置中的项目可信记录，影响该项目配置层是否参与；未记录时由原版信任流程决定 | 对应项目及其配置、MCP/Hook/插件等后续加载 | 不能为使插件开关生效而静默信任整个项目；也不因此让本轮未生效的项目技能规则突然有效 | 项目详情/原版信任流程，Agent 设置只读说明；保持现有记录 | 前轮隔离行为、定义 |

原版要求见[配置参考的 requirements 部分](https://learn.chatgpt.com/docs/config-file/config-reference)。原版协议没有返回某项完整要求时，标明信息不足；不通过读取受保护凭据或猜测企业策略补齐。

## 十、推荐纳入 Agent 管理的最终取舍

| 去向 | 建议内容 | 理由与默认行为 |
| --- | --- | --- |
| Codex 设置的常规区 | E01 实际运行环境、E02 必要路径/来源、E03 独立连接状态 | 直接帮助理解本应用管理谁、保存到哪里；只读身份不需要新开关 |
| Codex 设置的高级技能区 | S01–S05 已有规则，S06 目录信息预算 | 规则保留，优先修正命名空间/缓存路径风险；预算默认继承，不擅自设数值 |
| 可评估的高级默认区 | P01 插件继承默认、A01–A05 连接器默认策略 | 有真实字段，但首次实施前补具体作用和审批模式用例；不要一次加入全部按钮 |
| 具体资源详情 | S09 技能调用元数据；P05–P11 插件服务/工具；A06–A16 连接器/连接/工具 | 只有指定资源才知道实际适用性和权限，不在 Agent 设置堆重复列表 |
| 专属管理页 | Hook、市场、独立 MCP | 分别有来源、生命周期、授权及验证要求；Agent 设置可提供入口，不复制相同 CRUD |
| 只读或内部维护 | P12–P15、H02/H03 的哈希值、M05/M06、R01–R04 | 用户可能需要理解状态，但这些不是自由编辑的偏好值 |
| 当前不优先做普通控件 | S07/S08 的广域行为、S10 运行期根、A17 指令块、F01–F06、T02、C07/C08/C11 | 有的原版支持、有的尚欠宿主/执行证明；接入与否由当前产品需要及验证决定，不称为“原版不可用” |

建议的实施顺序：

1. **先修正已有语义**：实际配置来源、用户默认/项目覆盖/账号状态、删除覆盖与显式启用的区别、命名空间技能规则与更新后的延续。保持当前界面基线。
2. **再补少量确有价值的默认项**：技能目录预算等。默认保持继承；没有原版有效值证据时不在 UI 伪造固定默认。
3. **再补具体资源权限**：用实际 MCP/连接器/插件 Hook 隔离场景验证服务开关、工具集合、审批、输出与信任变化，然后在相应详情闭环。
4. **运行期/宿主能力单列研究**：额外目录、自定义 Settings view、旧客户端兼容等，不用现有接口对我们自己的进程生效来声称已经改变官方 App。

## 十一、容易误用的字段与产品说法

| 容易混淆的说法/实现 | 正确区分 |
| --- | --- |
| “插件总开关” | F01 是运行能力，P01 是未单配插件的默认，P02/P03 是本地单插件设置，P04 是账号服务操作 |
| “逐工具都写 enabled” | A12 的连接器工具有 enabled；插件 MCP 工具使用 P06/P07 清单，McpServerToolConfig 只有 approval_mode/output_token_limit |
| “全局默认都能套同一结构” | apps._default 没有 default_tools_enabled；plugins._default 也不是 app 审批配置对象 |
| “恢复默认就是写 true” | 恢复继承移除覆盖；最终值仍取决于剩余配置与策略 |
| “技能目录已配置就会影响所有 Codex” | S10 只证明当前进程；不同配置根/方案/宿主会话分别处理 |
| “允许技能自动调用就是启用技能” | S09 是调用选择策略，S01 是启停；插件/服务能否加载还要单独满足 |
| “允许某工具等于已有 OAuth 权限” | 本地工具策略、账号插件状态、第三方授权、管理员约束是不同层 |
| “目录 token 预算可以加快扫描” | S06 控制模型初始目录内容，不减少磁盘或网络发现工作 |
| “市场更新时间是自动升级计划” | M06 是观察时间；M07 才是有实际内容影响的操作 |
| “隐藏内部组件就是禁止运行” | P15 仅普通管理展示，原版仍维护/注入运行能力 |
| “schema 有字段就已经产品闭环” | 类型识别、保存读回、实际服务效果、账号权限和宿主更新分别验证 |
