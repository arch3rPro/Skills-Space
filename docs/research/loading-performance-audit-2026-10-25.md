## 复现与原因

用项目相同 React 19.2.8 的真实 effect 生命周期，调用实际 useCodexManagement 和插件目录组件，将原生/网络端替换为隔离响应并记录命令与参数。原始复现 `node .scratch/loading-probe/probe.mjs` 在切换语言后失败：目录命令由 1 增至 2，账号状态命令由 2 增至 3。原始目录命令内部还执行 inspect_catalog，因此语言变化不只是更换文案，而是整套本地状态与账号读取。

| 链路 | 查到的问题 | 当前处理 |
| --- | --- | --- |
| 添加插件切换语言 | zh effect 清空目录并重跑原生清单，分类还受父级 loading 翻转触发 | 复用已验证清单；首次加载另一语言只请求服务端目录/分类文案，切回已加载语言复用；保留原内容直到新语言返回 |
| 普通清单与 Codex 插件 | 普通清单完成前已另发插件扫描，稍后 initialSnapshot 到达可再启动一次 | 等普通清单完成；同一上下文正在执行的请求复用 promise；完整结果直接接收 |
| 原生 Agent 读取 | Hermes、Pi、Codex、DSH 顺序启动独立只读子进程 | 四个检查并行，仍按原先顺序合并资源归属与技能状态 |
| Pi/Hermes 页面 | 通用清单已检查相同配置，页面进入后再读一次 | 清单返回本次检查结果，页面复用；保存/回读同时更新对应观察结果 |
| 市场保存 | 并发启动插件清单及包含清单的目录刷新 | 按当前页面走一条刷新链路 |
| 写入后的全局清单刷新 | 已拿到原版完整回读，随后普通清单又引发全量插件读取 | 同一次操作的普通清单刷新复用已验证回读；技能/插件写入仍补齐完整状态 |
| 分类列表 | 父级 loading 变化会丢弃页面、重发请求，返回语言也重读 | 依赖实际查询、原生身份/指纹与语言；最多保留 8 个本组件内的页面结果，手动刷新清除 |

官方目录的分类名称由接口按 zh-CN/en 返回，并非全部是本地界面文案。首次切换到尚未读取的语言仍有轻量文案请求；不会再扫描 Agent 或插件。没有编造本地分类翻译。成功目录结果只在当前活动上下文保留两种语言；失败/未授权不缓存为成功，授权、插件变化、目标变化和手动刷新按现有流程重新读取。安装/启停/卸载/升级之前的原版校验与回读不从展示缓存授权。

## 2026-10-26：托管技能的完整 App 路径补查

同一两个项目的隔离响应，记录初始化及“全局 Codex → 项目 A Codex → 全局 Codex”：

修正：侧栏复用 Engine.agents 的轻量只读命令，不为显示 Agent 名单扫描技能；App 会话内按主机、全局/项目及 DSH 上下文复用已完成库存，并合并在途读取；托管页直接接收库存中的 Codex 原生观察，进入原生技能/插件页面再补所需完整目录。手动刷新和操作使展示缓存失效，写入仍走原版校验及真实回读，未将缓存用于授权。没有新增持久缓存、定时器、提示或页面。

缓存归属只在已接受读取键匹配时更新，避免 DSH context 变化把旧库存写进新键。只读目录回复与写入回读分开处理，手动全量刷新开始后迟到的目录结果不能覆盖新读取。实际 App 回归还复现了“刷新进行中，当前技能开关仍可操作，写入回读成功后旧刷新又覆盖状态”的交错；因此在实际技能写回处使旧库存请求失效，并结束旧加载状态，普通只读初始观察不取消刷新。测试使用当前挂载的开关，未抓取已卸载 callback 伪造交错。

以上为请求数量的确定性复现，不是用户环境的耗时承诺。真实原生隔离计时、覆盖边界及最终构建结果在本节后续记录。此前 GUI 工具的不可用状态不算本轮界面验收通过。

### 已加载插件数量消失的回归修正（2026-10-26）
