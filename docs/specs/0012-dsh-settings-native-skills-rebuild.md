## 1. 交付目标与范围

交付三处可实际操作的页面，而不是换皮后仍只有配置诊断：DSH 技能设置、全局原生技能、项目原生技能。普通使用不需要理解 bundle/entry/rank；这些内容仅在配置来源和必要诊断里出现。原生清单以可静态定位的文件资源为主要交付范围；不启动插件收集动态注册，不把未枚举的运行时贡献计成完整会话清单。

本批包含：

- Desktop 与本机 CLI/Web 的安装身份、HOME、Profile 和 preset 上下文分开读取；必要选择在重启后保留。
- 所选配置的技能目录、默认发现和监听设置；正确显示继承与覆盖，并按实际结构写入。
- 全局／项目原生资源的发现、预览、目录定位、调用策略、独立资源废纸篓卸载及批量操作。
- 已有目录接入，以及复用原版 `skills init` 创建本地原生技能；不自建安装器。
- 当前 Agent 与 preset 隔离；托管内容／共享内容／打包内容保持其生命周期归属。

本批不包含：插件商店、插件安装/更新/卸载/启停；模型与认证、账号、Agent loop/子代理等完整 DSH 控制台；Agent preset 创建/删除/全文编辑；更改真实 DSH 会话或新会话默认 preset；远端 Web Host 配置；内置/插件技能的独立卸载；自建来源记录库或通用新安装后端。

preset 在本批是“查看／编辑哪个 Agent 的技能设置”的选择，不是 DSH 会话切换。父 preset 配置物化仅限第 4 节明确提出的技能目录写入，不扩张为任意 preset 编辑器。该范围变化已由用户明确批准。

## 2. 页面职责与布局

### 2.1 设置 → 智能体 → DeepSeek Harness

参考现有 CodexSettings／PiManagement；保留外层设置标题、Tabs、BackButton、22px AgentLogo、共同宽度及共享 Card/Field。底部右对齐动作行：次要操作在前，保存最后；无额外“未保存”标签，沿用离开/关闭草稿确认。

| 区块 | 内容／控件 | 行为 |
| --- | --- | --- |
| 页头 | 返回、DSH 标识、重新读取 | 不重复外层设置标题，不放技术说明横幅 |
| 配置方案 | DSH 安装、配置方案、Agent 预设组合为一个字段 | 仅多选项时提供选择器；固定身份简洁显示，Desktop 不重复展示固定 desktop。多 provider 才出现额外选择 |
| 技能目录 | 包含默认目录、附加目录列表（添加/移除）、默认目录位置；高级项保留 provider 的 dshHome / agentsHome 覆盖 | 默认显示 ~；移除目录配置不删除文件。列出实际计算根及可点击位置，不将默认候选当有效配置 |
| 技能监听 | 自动监听；折叠的轮询、稳定等待、间隔、项目数、链接目标设置 | 一般用户只见核心开关；数值用现有字段错误样式，正整数校验 |
| 配置来源（折叠） | 所属安装/版本、实际文件、继承或覆盖；必要的只读原因 | 不显示密钥和无关完整配置；不在主界面要求用户选择 entry id 或理解 rank |
| 动作行 | 适用的恢复动作、保存 | 保存后回读新值；按实际能力说明“已生效”或“重新启动后使用”，不一律承诺热更新 |

“配置对象”的 Harness HOME 表示实际所属配置位置，不因修改 provider 的 dshHome 技能根参数而迁移 Profile 或用户数据。

设置页移除“全局／项目技能发现范围”选择。Profile 保存会影响使用它的所有项目；项目只在原生技能页决定发现 cwd，不能让用户误以为这次保存仅属于当前项目。目录与技能清单诊断属于原生技能页；设置页不再展示候选技能清单，配置来源仅保留必要来源信息，读取异常按需显示。

只读只作用于相关字段/条目。动态某字段不自动封锁无关根条目；但不能安全保存完整父配置时，明确阻断该父目标，不假装能局部保存。未知配置能力不伪装成“上游禁止”。

### 2.2 全局 → DeepSeek Harness → 原生技能

参考现有原生技能库存，不创建第二套卡片或设置框架。

- 沿用托管/原生 Tabs、共享工具栏、搜索、刷新、批量选择和库存 Card。
- 工具栏提供必要的配置方案/preset 选择；沿用设置中的默认选择，允许该范围独立选择。来源筛选只在存在多种来源时出现，菜单只呈现实际有的来源。
- 顶部目录使用当前配置实际启用的全局 DSH、共享及附加目录，多个根使用现有目录组合；不固定为 ~/.agents/skills。
- 主要新增入口为「创建技能」；「添加技能目录」进入同一配置的目录设置。原生页不放一个实际上会安装到“托管”页的模糊安装按钮。
- 卡片仍是名称、摘要、紧凑来源/身份、既有操作；不增加“符合规则”“未核验当前会话”“已解析”等正常提示。调用方式不放成卡片内 Select。
- 常态只提供必要操作，异常才说明格式错误、无法读取或同名覆盖；某技能在本批不可操作时，原因在对应动作和详情里呈现，不给整个页面挂只读横幅。

全局列表不自动并入项目根。显式附加根是 Profile 级配置，可以在多个查看范围出现，但不改变实际文件归属，也不创建项目副本；其路径与来源保持真实。共享文件不因此获得独立卸载或内容编辑资格。

### 2.3 项目 → DeepSeek Harness → 原生技能

结构与全局保持相同，额外遵循：

- cwd 为所选项目；DSH 项目根按最近 .git 祖先，没有 Git 时为该目录。只在实际不同且影响操作时显示解析后的根与原因。
- 顶部目录与列表共用同一份读取结果。项目 .dsh/skills、.agents/skills 和当前上下文附加目录按真实归属呈现。
- HOME 的全局文件参与同名覆盖计算，但不混入项目库存。项目链接指向全局内容仍保留项目路径身份，同时执行共享保护。
- 项目页进入「技能目录设置」时，明确这修改的是所选 Profile，而不是创造一个 DSH 不读取的项目配置文件。
- 关闭默认发现后不能继续展示默认目录；显式自定义根和显式 bundled 根按上游规则保留。没有启用根、根存在但无技能、读取失败是三个不同状态。

## 3. 原生技能操作合同

| 资源／动作 | 查看、预览、定位 | 调用方式 | 废纸篓 | 更新／安装 |
| --- | --- | --- | --- | --- |
| DSH 独立目录技能或扁平 Markdown | 允许 | 修改该文件原生调用键 | 目录整体或单 Markdown；附件影响按实际格式说明 | 无来源不虚构更新；创建走原版 init |
| 与其他 Agent 共享／CLI 托管文件 | 允许 | 本批不修改其正文/frontmatter；只有实际存在的 Agent 配置动作可用 | 不经独立原生卸载删除 | 托管生命周期仍走原版 skills CLI |
| Desktop/插件打包资源 | 可读且有路径时允许 | 不写包内文件 | 不允许独立移除 | 插件生命周期不在本批，无占位按钮 |
| 运行时 provider、无稳定文件路径 | 仅展示能够证明的元数据 | 不虚构文件控制 | 不允许 | 本批不连接会话 RPC伪造全量目录 |

详情复用现有 SkillDocument、元数据和更多菜单。仅在当前 DSH 原生资源中提供四种调用策略：模型与手动、仅手动、仅模型、均禁止；不把这些项放到托管技能详情、Pi 或 Hermes。既有源码/Markdown预览保留；本批不新增全文 Markdown 编辑器，提供实际文件/目录定位用于外部编辑。

调用策略只影响后续相应发现/调用边界，不声称清除已进入会话的指令。修改原生 frontmatter 保留正文、附件、其他键、注释与原有换行。

创建流程复用既有 init 向导/确认/结果：选择本范围中实际启用且可写的原生目录，名称使用 DSH 合法小写 kebab-case，确认目标后调用原版 `skills init`，不覆盖已有 SKILL.md；回读后验证 DSH 格式并刷新当前原生列表。若默认根未存在，仅创建经确认的目标目录，再调用原版 init。使用已有目录通过添加附加根接入，不复制/移动用户内容。从 GitHub 安装仍由托管技能现有安装入口完成，不另造“.dsh 仓库安装器”。

批量操作沿用共享 BulkSelectionBar、动作菜单、确认与逐项结果：

- 选中集与每个动作的可操作集分开。按本次调用修改／废纸篓动作计算资格，不用一个全局 canManage 或全选交集锁住所有操作。
- 操作前明确本次可执行数量及不可执行项原因；不静默跳过，也不因一项不合格让其余合格项全部不可操作。废纸篓必须列出实际目标与附件影响。
- 复用已有原生执行服务，逐项核验并报告成功、失败、未执行；已成功项不因后项失败被标成失败，不自动回滚或重复操作。单文件过期不修改它；配置上下文整体变化则停止剩余依赖该上下文的写入并要求重读。
- 同一物理目标只执行一次；不能因同一技能出现在多个 provider/preset 而重复移除或写入。

## 4. 技能配置保存与恢复：已批准合同

### 普通根 provider

复用现有 Profile patch 写入、原版组合和锁。保存只改所选 provider 的技能字段，保留未知字段；恢复继承移除目标 config 覆盖，保留其他条目和元数据。不能仅凭新版本号被排除，也不能未核查原版合同就开放任意版本。

### preset 内 provider（本次已批准）

目的：使当前默认 Desktop/Web 的常用 preset 能实际编辑技能目录，而不只是查看。

上游普通 Settings 不提供这些字段的局部写入；采用其父 preset 完整 config 覆盖语义：从正确安装对应的已组合声明出发，保留父 preset 的其他字段和完整 plugins，修改唯一定位的技能 provider，再写所选 Profile 用户 patch。用“preset 所有者 + child 路径”定位，禁止按全局裸 id 查找。

该保存只在已确定父对象结构且可保留未解析表达式/未知字段时执行；不执行表达式、不迁移 provider 到全局、不重建工具或 persona 列表。改写一个 preset 不改其他 preset、HOME patch、bundle 或 Desktop 壳配置。

**必须明示的效果：** 保存后该父配置成为完整用户覆盖，后续 bundle 的父配置变化不会自动合入。首次物化前用共享确认对话框说明范围和影响；不能声称只保存了几个完全独立继承的技能字段。

恢复动作区分：

1. 普通根 provider 的「恢复继承」是真正移除该 provider 的覆盖。
2. preset 内将技能字段改回下层当前值，只是恢复当前默认值；父配置仍然物化，不能称为已恢复动态继承。
3. 真正的「恢复预设继承」需要移除父 config 覆盖，会影响该父配置中其他自定义值。必须先展示差异和影响后确认；存在其他自定义时不能悄悄删除它们。继续复用现有差异/确认能力，不为此创建一套历史/来源数据库。

本次只为技能设置物化父 preset，不增加其他 preset 编辑入口；复杂或无法完整重建的父目标仍按条目只读。

## 7. 验收矩阵与设计门禁

通用隔离 fixture，不以个人配置、安装路径或插件清单制作适配。至少覆盖：

- 安装/配置：仅 Desktop、仅 CLI/Web、两者并存；相同/不同 HOME；desktop/web/custom Profile；相同 child id 的多个 presets；无配置、缺依赖、动态字段和上层覆盖。
- 设置写入：默认根、附加根、监听及高级数值；真正继承与当前默认值恢复的区别；父 preset 的未知字段/条件表达式/其他 child 保留；其他 preset/Profile/HOME/打包文件不变；外部改动冲突与重启回读。
- 库存：全局/项目无泄漏；最近 Git 根/无 Git 项目；关闭默认发现；自定义目录；扁平 Markdown/目录技能/链接；同名覆盖；空根与失败区分；配置或 preset 切换后不显示旧请求结果。
- 操作：合法/非法 DSH 格式；四种调用策略正文及附件保留；创建不会覆盖已有技能；独立资源移至废纸篓；共享/CLI/内置保护；未知状态不误报冲突；批量混选按动作计算；部分失败、过期和同物理路径去重。
- 界面：Settings/Codex/Pi 参照一致；全局/项目相同卡片、工具栏、详情和弹窗；不出现卡片内调用下拉框或无关 Agent 控件；无正常状态诊断噪声；键盘/焦点、长路径、加载/空/错误/忙状态；浅深主题、默认/窄窗口、14/16/18字号。

主代理完成代码后，按项目规则交 test_coverage 负责回归覆盖、staging、pnpm build 和 CI=false pnpm tauri build --debug --bundles app，准备独立 HOME 与应用 fixture。然后 ui_reviewer 做静态和实际 Tauri 流程验收；主代理修复生产代码，相关项定向复验。未通过设计基线即不算完成。真实 DSH 会话未核验时不宣称热加载成功；本批也不为了证明它额外建设远程/会话管理功能。

已按批准范围实施；功能、构建与 UI 验收结果见第 9 节。
